# 0014. 本机 Hermes 执行与真实性运行时守卫

- 状态: 已接受
- 日期: 2026-07-24
- 决策者: AgentPulse 项目所有者

## 背景

AgentPulse 的公司管理工具可以在服务端执行，但服务端无法访问老板电脑上的项目目录。此前聊天入口还允许 DeepSeek 的普通文本把未执行的动作说成已完成，造成了比“能力不足”更严重的信任问题。

## 决策

Hermes 仍是唯一员工运行时。API 负责公司事实、聊天、Run、设备/项目绑定和审批；Electron 主进程负责本机 Worker、绝对路径映射和真实执行。用户选择的项目根目录只保存在本机安全存储，云端只保存项目 ID、显示名、路径哈希、设备绑定和授权范围。

所有模型工具调用先经过统一解析、参数校验、范围校验和 execution receipt。没有真实 handler 结果和回执时，系统不得显示“已创建”“已读取”或“已完成”。DeepSeek DSML 只作为输入格式解析，不能直接作为执行协议。

DeerFlow 只借鉴 Run 恢复、悬空工具调用处理、沙箱路径校验、输出截断和上下文账本思想；不引入 LangGraph，也不替换 AgentPulse 的公司协作层或 Hermes ACP。

本机首个执行切片只允许已授权项目内的只读分析。写文件、命令、浏览器登录、电脑控制和业务外部动作必须进入相应审批运行时；本轮不能安全执行的能力显示阻塞并保留失败回执。

## 理由

云端不能通过网络推断或访问用户本机绝对路径；把 Hermes 放在 API 服务器上只能操作服务器 workdir，不满足桌面产品目标。把设备 Token、项目根目录和文件操作放进 renderer 也会扩大攻击面，因此这些状态由 Electron 主进程管理，Token 使用 `safeStorage` 加密。

## 后果

本机 Worker 可以在 API 重启后继续领取持久 queued Run，客户端可以按 Run 事件恢复轨迹。生产分发还需要把固定 Hermes runtime、员工 profile 供给和 DeepSeek 运行凭证安全同步到客户端；在这部分完成前，安装包遇到缺少本机 profile 会诚实失败，不能宣称完整离线开箱即用。
