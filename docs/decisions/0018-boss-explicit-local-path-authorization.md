# 0018. 老板在桌面消息中明确给出的本机路径即授权

- 状态: 已接受
- 日期: 2026-07-26
- 决策者: AgentPulse 项目所有者

## 背景

旧流程要求老板先去设置页选择项目目录，再回聊天发任务。老板直接在桌面聊天中给出一个真实绝对路径时，renderer 会把消息发送到 API，但不会建立 `local_project`，最终出现“已授权本机项目路径”与“尚未授权项目目录”同时存在的矛盾。并发调用 `startLocalWorker()` 还可能为同一个 Electron 进程注册多个设备身份，使项目绑定和 Run 领取落到不同设备。

项目所有者确认老板秘书是公司内权限最高的员工，应能像老板本人一样使用老板明确交付的电脑上下文，而不是被额外的设置页步骤拦住。

## 决策

老板在 AgentPulse 桌面聊天中明确输入一个当前真实存在的本机绝对目录或文件路径，视为对该路径的本次本机工作授权。Electron 主进程在路径离开设备前执行 `realpath`、存在性和类型检查，将目录或文件所在目录登记为当前设备的 `local_project`，API 仍只接收显示名、路径哈希和授权范围，不保存绝对路径。renderer 使用返回的 `local_project_id` 将消息直接排入 Local Worker。

此授权适用于小秘和其他已获相应员工能力的 Hermes profile。小秘在组织权限上最高，但职级不构成绕过系统安全门的依据：读取可在明确路径范围内自动执行；写入、终端、浏览器登录、`computer_use` 和外部动作继续走持久审批与回执。没有老板明确提供或选择的路径时，不因“小秘”身份自动开放整个用户主目录。

`startLocalWorker()` 必须是进程内幂等且并发单飞。登录恢复、设置页和失效 Token 重连不能为同一运行中桌面实例并发创建多个设备身份；强制重连只替换该实例之前的精确设备 ID。

## 理由

消息中明确给出路径本身就是老板的自然语言授权意图，再要求去设置页重复确认没有增加有效安全性，只制造断链。路径验证和绝对路径保留在 Electron 主进程，可同时满足低摩擦体验、云端最小知情和项目范围隔离。危险动作审批表达的是老板最终控制权，不是对秘书能力的削弱。

## 后果

老板可以直接把项目路径和任务一起发给小秘，首条消息即可创建并执行本机 Run。普通云端消息、Webhook 或不存在的路径仍然 fail-close。路径出现在聊天消息中会被 API 脱敏为 `[已授权本机项目路径]`；审计和回执继续使用虚拟路径。完整 `computer_use` 与浏览器执行器仍需按 TD-14R-P1 完成，不得因本 ADR 被宣称为已实现。
